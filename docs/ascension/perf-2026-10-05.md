# Frame-rate investigation, 2026-10-05

Report: "the game is super laggy". Branch `gameplay-hud-kestrel-reach`. Machine: Dell G15, RTX 3050 laptop GPU (PRIME
offload), Godot 4.7.2 Compatibility (OpenGL) renderer, 1920x1080.

Every number here was measured, not estimated. Each run used a separate QA instance from `tools/qa/launch_ui.py` with its
own bridge, so the user's game was never touched. The "before" build is `git archive HEAD` of the branch before these
commits, run with the same driver.

## How it was measured

- `tools/qa/ui_driver.gd` gained five QA events. All are read-only except `tweak`, which changes presentation only.
  - `perf`: records every frame for N seconds and writes `perf_<name>.json`. Per frame it logs:
    - frame time and engine counters: draw calls, primitives, objects, nodes
    - GPU and CPU render time from `RenderingServer.viewport_get_measured_render_time_*`, for the main view and the minimap
    - GDScript time for the whole node tree, taken from bracket nodes at process priority -100000 and +100000
    - whether the frame polled a snapshot or rebuilt the HUD view model
    - how many bridge units moved
    - HUD layer rebuilds
    - Runs uncapped (vsync off), or at the shipped 60 Hz.
  - `sections`: times one piece of per-frame work at a time (parse, entity sync, HUD view model, hover, and so on), or any
    expression.
  - `tweak`: switches minimap, shadows, split count, shadow distance, MSAA, UI, terrain and dressing for A/B windows.
  - `ui_sweep`: hides each UI layer in turn and measures the frame.
  - `eval`: reads one value.
- `Performance.TIME_PROCESS` is a per-second maximum, not a per-frame cost, so it was not used.
- Godot stops drawing while its window is minimized: GPU time reads 0 and the counters go stale. Every window was checked
  for `gpu_ms > 0` and re-run if it was 0. The QA window was kept in the window manager's "below" layer so it never covered
  the user's windows.
- States measured: Kestrel Reach and Survival, at default zoom (8.8) and fully zoomed out (24). Each was measured idle (the
  build-up before wave 1) and mid-combat (about 2 s after wave 1 spawns). The last window ran at the shipped 60 Hz cap
  with vsync.

At the shipped 60 Hz cap, the before build missed frames: p95 was 21 to 25 ms, so one frame in twenty took two vsyncs or
more. After the fixes, p95 is 16.7 to 17.5 ms. Before the fixes, moving units visibly stepped about 8 times a second

A quiet-machine run earlier the same morning, before any fix, had Kestrel idle at 85.4 fps (11.67 ms, 2403 draw calls).
Under the same conditions the first two fixes took it to 5.4 to 5.8 ms (847 draw calls).

## Causes, ranked by measured cost

1. **World marks: the wave route drawn as single dashes, about 5.5 ms a frame on Kestrel.**
   - `world_marks.gd` drew every dash of a dashed stroke as its own antialiased polyline. That costs about three draw calls
     per dash, and the inbound wave route on Kestrel (5 beams, about 133 dashes at default zoom) is redrawn every frame.
   - Hiding WorldMarks alone took the Kestrel idle frame from 11.5 ms to 5.96 ms, and draw calls from 2406 to 2001.
   - Survival has no wave route, which is why Kestrel was about twice as slow.
   - **Fixed:** a stroke is now one antialiased `draw_multiline`, and dashes wholly off screen are skipped. A pixel diff of
     Kestrel at both zooms found no pixel differing by more than 40/255. Kestrel went to 7.0 to 7.6 ms.
2. **Minimap re-rendered the whole battlefield every frame: about 1.7 to 1.9 ms and 1,160 draw calls.**
   - The minimap is a SubViewport sharing the game's World3D, with `UPDATE_ALWAYS`. Every frame it drew every mesh again
     from its own camera, including the directional shadow passes.
   - **Fixed:** it now renders 5 times a second (`MINIMAP_INTERVAL` 0.2 s, `UPDATE_ONCE`), and not at all while the HUD
     is hidden. The view box and the marks over it are HUD controls and are unaffected.
3. **Units moved only when a snapshot was polled (8.3 Hz).**
   - Units glided toward the polled position by 38 percent once per poll, so only about 11 percent of frames moved any
     unit. That reads as stutter at any frame rate.
   - **Fixed:** the glide runs every frame with a frame-rate-independent rate. Over one poll it covers the same 38 percent,
     so units trail the simulation exactly as before. Moving share went from 0.10-0.14 to 1.0.
4. **Pointer position asked the X server several times a frame.**
   - `Viewport.get_mouse_position()` is a synchronous X round trip, measured at 150 to 640 µs per call on this desktop.
   - It was called every frame by the hover hex and by edge panning, and by the HUD view model on rebuild frames.
   - **Fixed:** the game keeps the position from mouse events. It falls back to asking only before the first event and
     after the pointer leaves the window, so edge panning keeps its behaviour. Per call: 1 µs. Hover went from 588 to
     203 µs, and the camera update from 247 to 22 µs.
   - This also removed most of the 11 to 12 ms single-frame GDScript spikes on plain frames: their max is now 1.5 to 3.7 ms.
5. **Snapshot poll and HUD rebuild landing on the same frame.**
   - A poll frame (read and parse about 25 KB of JSON, sync entities) cost 4.3 to 8.3 ms of GDScript, and a HUD rebuild
     frame cost 2.6 to 5.1 ms.
   - When both fell on one frame, which happened every second or so, it averaged 9.5 to 19.9 ms, with a max of 30.9 ms.
   - **Fixed:** the HUD rebuild steps off a poll frame by one frame. Combined frames went from 2 to 7 per window to 0.
   - The territory card (about 0.6 ms of every rebuild) is now cached until the construction zone changes.
6. **Other software on the machine.**
   - The heaviest load seen was another agent's software-rendered (llvmpipe) Godot QA at about 700 percent CPU, together
     with dotnet builds. During that, Kestrel fell to 42 fps with p95 above 50 ms, in a build that ran at 85 fps on a quiet
     machine.
   - Sunshine (NVENC) showed about 43 percent GPU utilisation while it was streaming.
   - None of this is in the game, but it was a real part of the lag.
7. **Shadows, MSAA and the bridge are minor.**
   - Directional shadows (4 splits, 120 m): turning them off saves about 840 draw calls zoomed out but only 0.3 to 0.6 ms.
     2 splits, 50 m distance, and 4 splits at 50 m measured no difference. Kept as they are.
   - MSAA 2x off: no measurable change.
   - The bridge uses 0.85 percent of one core (0.28 ms per tick at 30 Hz). The snapshot is 21 to 29 KB, about 400 bytes
     per entity. The keys this branch added (ground, ground_table, regions, wave_route, supply_links) are about 3.3 KB.
   - The parked bridge suspects (kestrel_wave_route and is_kestrel_map recomputed per snapshot, min_step_cost rescans)
     are inside that 0.28 ms, so they were not changed. The Rust code and the golden hash are untouched.
   - The other parked suspects (pause view model, region map, roster) were never on the hot path in the measured states.

## Not fixed (largest remaining costs)

- **HUD text drawing, 3 to 5 ms a frame.**
  - Hiding the HUD takes Kestrel from 8.3 ms to 3.3 ms at default zoom, and from 9.5 to 5.6 ms zoomed out.
  - The HUD is only 191 canvas items, but it issues about 4,200 canvas commands a frame. `text_box.gd` draws letter-spaced
    and mono text one glyph at a time with `draw_char`, and Godot replays every command each frame.
  - Fixing it means caching the HUD to a texture, or fewer and larger text runs. Both risk the pixel-verified layouts, so
    it is left as the next step.
- **Poll frames, 4.3 to 7.4 ms of GDScript, 8 times a second.**
  - JSON parse is 1.4 to 2.1 ms under load, entity sync 0.75 to 1.0 ms, and the HUD view model and apply 1.3 to 1.8 ms each.
  - Parsing on a worker thread would take the parse off the frame. That is a larger change than this pass allowed.
- **Zoomed-out Kestrel combat** has the most variance (75 to 110 fps across runs). It is CPU render time: about 1,900 draw
  calls, most of them the 3D world and its shadow passes at that view size.

## Budget for the world-art work (MultiMesh ground, trees, rocks)

Measured after the fixes, Kestrel idle at default zoom:

| Part | Draw calls | Frame |
|---|---|---|
| 3D world including 4-split shadow passes (HUD hidden) | 574 | 3.3 ms |
| Same, zoomed out | 1351 | 5.6 ms |
| Whole frame | about 895 (1,710 zoomed out) | 6 to 9 ms |

Primitives are about 155k at default zoom and 240k zoomed out. GPU time is about 2 ms of a 16.7 ms frame at 60 Hz.

- Capture the world-art baseline **after** these commits. Draw calls fell from about 2,400 to about 900, so a
  "baseline + 120" budget measured against the old numbers would allow over 1,500 extra.
- A shadow-casting mesh is drawn once for the camera and once per shadow split it touches, so up to 5 times. Keep shadow
  casting off for props, as the plan says.
- Use one MultiMeshInstance3D per prop kind. Never one node per tree or rock: at about 1 to 5 draw calls each, 200 trees
  would cost more than the whole world does today.
- The minimap renders the same World3D 5 times a second. Every prop also costs there, at about one twelfth of the frames
  at 60 fps.
- Budget: at most 120 extra draw calls and 150k extra primitives at both zooms. Kestrel idle should stay at or under
  10 ms p50 on the RTX 3050 uncapped, which leaves 60 Hz headroom for the HUD's 3 to 5 ms.

## Regression tests

`godot3d/tests/test_frame_costs.gd` checks:

- the minimap render rate, and that it stops while the HUD is hidden
- that the HUD rebuild steps off poll frames, and is not held back when overdue
- off-screen dash culling, and that a stroke is built as multiline pairs
- that the territory cache is equal to a fresh computation and recomputes when the zone changes
- that the game reads the pointer from mouse events
- frame-rate-independent glide (18 frames and 1 frame over one poll land in the same place, at 38 percent)

## QA notes

- Driver clicks (`click` events) call `warp_mouse`, which moves the real cursor on a shared desktop. Zoom for these runs
  was set through `eval` instead.
- A GPU QA window opens on the user's display. It was put in the "below" layer and the user's focus was restored after
  each launch.
